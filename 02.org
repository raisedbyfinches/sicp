** Rational data types

Haskell actually has a data type where a rational number is represented as a pair (numerator and denominator) and both are tracked throughout its lifetime. This is ~Rational~ (though that's just a synonym for ~Ratio Integer~. They are stored in reduced form so along the way it has to be divided by its GCD. They make the denominator always positive so that the sign of the number is carried in the numerator.

This enables us to represent fractions without rounding errors (looking at you floating-point numbers). For symbolic computations and in certain domains this is useful because of the higher precision. Though the operations can be slower because of needing to calculate the GCD and when the size of the numerator and denominator grow significantly this can use a lot more memory.

So its not *completely* insane to build data types in this way.

** Exercise 1
Define a better version of ~make-rat~ that handles both positive and negative arguments. ~make-rat~ should normalize the sign so that if the rational number is positive, both the numerator and denominator are positive, and if the rational number is negative, only the numerator is negative.

#+begin_src scheme
;; Define a constructor for rational numbers
(define (make-rat n d)
  (let* ((g (gcd n d))              ; Compute GCD
         (numer (/ n g))            ; Reduce
         (denom (/ d g)))           ; Reduce
    (if (< denom 0)                 ; Ensure denominator is positive
        (cons (- numer) (- denom))  ; Flip signs if denominator is negative
        (cons numer denom))))       ; Otherwise, return as is
#+end_src

** Exercise 2

Consider the problem of representing line segments in a plane. Each segment is represented as a pair of points: a starting point and an ending point. Define a constructor make-segment and selectors start-segment and end-segment that define the representation of segments in terms of points. Furthermore, a point can be represented as a pair of numbers: the x coordinate and the y coordinate. Accordingly, specify a constructor make-point and selectors x-point and y-point that define this representation. Finally, using your selectors and constructors, define a procedure midpoint-segment that takes a line segment as argument and returns its midpoint (the point whose coordinates are the average of the coordinates of the endpoints). To try your procedures, you’ll need a way to print points:

#+begin_src scheme
(define (print-point p)
  (newline)
  (display "(")
  (display (x-point p))
  (display ",")
  (display (y-point p))
  (display ")"))
#+end_src

*** Solution

#+begin_src scheme
;; Constructor for points
(define (make-point x y)
  (cons x y))

;; Selectors for points
(define (x-point p) (car p))
(define (y-point p) (cdr p))

;; Constructor for segments
(define (make-segment start end)
  (cons start end))

;; Selectors for segments
(define (start-segment s) (car s))
(define (end-segment s) (cdr s))

;; Procedure to compute the midpoint of a segment
(define (midpoint-segment s)
  (let ((start (start-segment s))
        (end (end-segment s)))
    (make-point
     (/ (+ (x-point start) (x-point end)) 2)
     (/ (+ (y-point start) (y-point end)) 2))))
#+end_src

* Extended exercise: interval arithmetic

This has so much pre-amble. Essentially using an interval to capture a range of possible values. There's plenty of use cases of such a thing where the exact values aren't known but the bounds of uncertainty can be established.

Intervals:
 - represented by a lower and upper bound
 - extend arithmetic operations to work with intervals, producing new intervals encompassing all possible results of the operation

The key idea is that by working with intervals, we can carry uncertainty through the computations. This ensures results remain valid even with imprecise inputs.

** Exercise 8

Using reasoning analogous to Alyssa’s, describe how the difference of two intervals may be computed. Define a corresponding subtraction procedure, called sub-interval.

*** Solution
To compute the difference between two intervals $A = [a, a']$ and $B=[b, b']$ the smallest possible is the minimum of all of the differences and the upper bound is the maximum of all of the differences. So the subtraction of intervals could look like:

#+begin_src scheme
(define (sub-interval x y)
  (let ((a (- (lower-bound x) (upper-bound y)))
        (b (- (upper-bound x) (lower-bound y)))
        (c (- (lower-bound x) (lower-bound y)))
        (d (- (upper-bound x) (upper-bound y))))
    (make-interval (min a b c d)
                   (max a b c d))))
#+end_src

** Exercise 9

The width of an interval is half of the difference between its upper and lower bounds. The width is a measure of the uncertainty of the number specified by the interval. For some arithmetic operations the width of the result of combining two intervals is a function only of the widths of the argument intervals, whereas for others the width of the combination is not a function of the widths of the argument intervals. Show that the width of the sum (or difference) of two intervals is a function only of the widths of the intervals being added (or subtracted). Give examples to show that this is not true for multiplication or division.

*** Solution

The definition of the width from the above is:

#+begin_src scheme
  (define (width interval)
    (/ (- (upper-bound interval) (lower-bound interval)) 2))
#+end_src


1. When adding two intervals:
   - Interval 1: $[a_1, b_1]$
   - Interval 2: $[a_2, b_2]$
   - Resulting interval: $[a_1 + a_2, b_1 + b_2]$
   - Width of the resulting interval:
             \begin{aligned}
     width &= \frac{(b1 + b2) - (a1 + a2)}{2} \\
           &= \frac{(b1 - a1) + (b2 - a2)}{2} \\
           &= w1 + w2
     \end{aligned}
   - Thus, the width of the sum is a function only of the widths of the input intervals.

2. When subtracting two intervals:
   - Interval 1: $[a_1, b_1]$
   - Interval 2: $[a_2, b_2]$
   - Resulting interval: $[min(a_1 - b_2, a_1 - a_2, b_1 - b_2, b_1 - a_2), max(a_1 - b_2, a_1 - a_2, b_1 - b_2, b_1 - a_2)]$
   - Width of the resulting interval:
     \begin{aligned}
     width &= \frac{1}{2}max(a_1 - b_2, a_1 - a_2, b_1 - b_2, b_1 - a_2) \\
           &- \frac{1}{2}min(a_1 - b_2, a_1 - a_2, b_1 - b_2, b_1 - a_2)
     \end{aligned}
   - However, after simplification, it can be shown that the width of the resulting interval is still ~w1 + w2~, because the subtraction operation does not introduce additional dependencies beyond the bounds of the input intervals.

3. When multiplying two intervals:
   - Interval 1: $[a_1, b_1]$
   - Interval 2: $[a_2, b_2]$
   - Resulting interval: $[min(a_1*a_2, a_1*b_2, b_1*a_2, b_1*b_2), max(a_1*a_2, a_1*b_2, b_1*a_2, b_1*b_2)]$
   - The width of the resulting interval depends on the specific values of $a_1, b_1, a_2, b_2$, not just their widths. For example:
     + Interval 1: $[1, 2]$ (width = 0.5)
     + Interval 2: $[3, 4]$ (width = 0.5)
     + Resulting interval: $[3, 8]$ (width = 2.5, which is not $0.5 + 0.5$).

4. When dividing two intervals:
   - Interval 1: $[a_1, b_1]$
   - Interval 2: $[a_2, b_2]$ (assuming $0 ∉ [a_2, b_2]$ to avoid division by zero)
   - Resulting interval: $[min(a_1/a_2, a_1/b_2, b_1/a_2, b_1/b_2), max(a_1/a_2, a_1/b_2, b_1/a_2, b_1/b_2)]$
   - The width of the resulting interval depends on the specific values of $a_1, b_1, a_2, b_2$, not just their widths. For example:
     + Interval 1: $[1, 2]$ (width = 0.5)
     + Interval 2: $[3, 4]$ (width = 0.5)
     + Resulting interval: $[1/4, 2/3]$ (width ≠ $0.5 + 0.5$).

*** Solution

(define (div-interval x y)
  (if (or (<= (lower-bound y) 0 (upper-bound y)))
      (error "Division by an interval that spans zero is undefined")
      (mul-interval x
                    (make-interval (/ 1.0 (upper-bound y))
                                   (/ 1.0 (lower-bound y))))))
#+end_src

** Exercise 11
In passing, Ben also cryptically comments: "By testing the signs of the endpoints of the intervals, it is possible to break mul-interval into nine cases, only one of which requires more than two multiplications." Rewrite this procedure using Ben’s suggestion.

*** Solution
#+begin_src scheme
(define (mul-interval x y)
  (let ((lx (lower-bound x))
        (ux (upper-bound x))
        (ly (lower-bound y))
        (uy (upper-bound y)))
    (cond
      ;; Case 1: Both intervals are entirely positive
      ((and (>= lx 0) (>= ly 0))
       (make-interval (* lx ly) (* ux uy)))

      ;; Case 2: x is positive, y spans zero
      ((and (>= lx 0) (<= ly 0 uy))
       (make-interval (* ux ly) (* ux uy)))

      ;; Case 3: x is positive, y is entirely negative
      ((and (>= lx 0) (<= uy 0))
       (make-interval (* ux ly) (* lx uy)))

      ;; Case 4: x spans zero, y is positive
      ((and (<= lx 0 ux) (>= ly 0))
       (make-interval (* lx uy) (* ux uy)))

      ;; Case 5: Both intervals span zero
      ((and (<= lx 0 ux) (<= ly 0 uy))
       (make-interval (min (* lx uy) (* ux ly))
                      (max (* lx ly) (* ux uy))))

      ;; Case 6: x spans zero, y is negative
      ((and (<= lx 0 ux) (<= uy 0))
       (make-interval (* ux ly) (* lx ly)))

      ;; Case 7: x is entirely negative, y is positive
      ((and (<= ux 0) (>= ly 0))
       (make-interval (* lx uy) (* ux ly)))

      ;; Case 8: x is entirely negative, y spans zero
      ((and (<= ux 0) (<= ly 0 uy))
       (make-interval (* lx uy) (* lx ly)))

      ;; Case 9: Both intervals are entirely negative
      ((and (<= ux 0) (<= uy 0))
       (make-interval (* ux uy) (* lx ly))))))
#+end_src

** Exercise 16
Explain, in general, why equivalent algebraic expressions may lead to different answers. Can you devise an interval-arithmetic package that does not have this shortcoming, or is this task impossible? (Warning: This problem is very difficult.)

*** Solution
I think this is far too difficult for civil servants. So let's think about *why* its so hard.

The fundamental issue is that of _identity_ in interval arithmetic and is even a named problem. You can read more about it if you search for the *Dependency Problem*.

Identity in regular arithmetic is trivial. For example, if $x=5$ then every instance of $x$ is exactly 5. This means that, unambiguously, $x*x = 5*5 = 25$.

Now, taking this into the realm of interval arithmetic. If two $x$'s existed the value of one $x$ is not necessarily the same as another. For example, let us assume that is the interval $[3,10]$. Now $\frac{x}{x}$ could be $1$. That is, if it meant $\frac{3}{3}$ or $\frac{8}{8}$. However, its possible that it could mean $\frac{4}{9}$ or something else. These values are within the specified range and it is theoretically possible. The problem is, we don’t know what the values are.

There is no obvious way, mathematically, to introduce identity into interval arithmetic.
